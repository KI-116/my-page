# 🧠 回溯算法学习标签页总结

## 1. 回溯法是什么（核心定义）
回溯法 = **在集合中进行递归搜索的穷举算法**，本质是暴力搜索，只是可以通过剪枝减少无效分支  

## 2. 回溯法能解决哪些问题

- **组合问题**：从 N 个数中按规则选 k 个  
- **切割问题**：字符串按规则切割  
- **子集问题**：求所有符合条件的子集  
- **排列问题**：强调顺序的全排列  
- **棋盘问题**：N 皇后、数独等



## 3. 回溯问题的统一抽象：树形结构
所有回溯问题都可以抽象为一棵 **N 叉树**：  

- 集合大小 = 树的宽度  
- 递归深度 = 树的深度  
- 终止条件 = 到达叶子节点  

这也是回溯算法能用统一模板解决不同题型的原因。


## 4. 回溯算法模板（重点）
页面给出了完整的回溯模板：  

### **回溯三部曲**
1. **终止条件**：到达叶子节点，记录结果  
2. **遍历当前层的所有选择**（for 循环 = 横向遍历）  
3. **递归 + 回溯撤销**（递归 = 纵向遍历）  

### **伪代码结构**
```
void backtracking(参数) {
    if (终止条件) {
        存放结果;
        return;
    }
    for (选择：本层集合中的元素) {
        处理节点;
        backtracking(路径，选择列表);
        撤销处理结果;
    }
}
```

## 5. 回溯法的效率与局限
- 回溯法并不高效，本质是穷举  
- 剪枝可以减少搜索量，但无法改变穷举本质  
- 之所以使用回溯，是因为这些问题本身没有更高效的解法

# 🎯 **哈希表理论核心总结**

### 1. **哈希表是什么？**
哈希表（Hash Table / 散列表）是一种**根据关键码直接访问数据**的数据结构，本质上可以理解为“带哈希函数的数组”   
关键码（key）通过哈希函数映射到数组下标，从而实现 **O(1)** 的查找效率  

## 2. **哈希函数（Hash Function）**
哈希函数负责把 key（如姓名）转换成数值索引：

- 先通过 `hashCode` 将 key 转成数值   
- 若超出数组范围，再对 tableSize 取模，使其落入合法区间  

哈希函数的目标是：  
**尽可能均匀地把数据分布到哈希表中，减少冲突。**


## 3. **哈希碰撞（Collision）**
当不同 key 映射到同一索引时，就发生哈希碰撞，例如小李和小王都映射到索引 1   

常见解决方法：

### **① 拉链法（Separate Chaining）**
- 每个桶存一个链表  
- 冲突的元素挂在链表后面  
- 需要合理选择 tableSize，避免链表过长或空间浪费   

### **② 线性探测法（Linear Probing）**
- tableSize 必须大于 dataSize    
- 冲突时向后寻找下一个空位存放数据   

## 4. **常见三类哈希结构**
数组、set、map  

### **Set 系列（集合）**  
底层实现与特性如下（来自页面表格）：

- `std::set` / `std::multiset`：红黑树，有序，查询 O(log n)  
- `std::unordered_set`：哈希表，无序，**查询 O(1)（最常用于哈希法）**   

### **Map 系列（映射）**
- `std::map` / `std::multimap`：红黑树，有序，key 不可修改   
- `std::unordered_map`：哈希表，无序，查询 O(1)   
页面特别强调：  
**解决哈希问题时优先使用 unordered_set / unordered_map**，因为它们是哈希表结构，效率最高   



## 6. **哈希法的使用场景总结**
当你需要：

- **快速判断某元素是否出现过**  
- **快速查找是否存在某 key**

第一时间应该想到哈希法 

但哈希法是 **空间换时间**：需要额外的数组 / set / map 来存储数据 


## 📌 **一句话总结**
> **哈希表 = 用哈希函数把 key 映射到数组下标，通过 O(1) 查找实现高效判断与搜索；碰撞用拉链法或线性探测法解决；C++ 中 unordered_set / unordered_map 是最常用的哈希结构。**

# 🧠 动态规划（DP）总结

## ⭐ 一句话总览  
**动态规划 = 明确状态 → 找到状态转移 → 正确初始化与遍历 → 推导 dp 表 → 再写代码。**  
它的本质是：**每个状态由上一个状态推导而来**   


## 1. 什么是动态规划（DP）
- 动态规划适用于**存在大量重叠子问题**的场景，是最有效的求解方式  
- 与贪心的区别：  
  - **DP：状态由前一状态推导**（如 `dp[j]` 由 `dp[j-weight[i]]` 推导） 
  - **贪心：每次直接选局部最优，不依赖状态**
- 因此，像背包问题这种需要"组合推导"的，贪心无法解决


## 2. 动态规划的五步曲（页面核心内容）
页面强调：**只有五步都搞清楚，才算真正掌握 DP**。

### DP 五步曲：
1. **确定 dp 数组及其含义**  
   明确 `dp[i]` 或 `dp[i][j]` 表示什么，这是最关键的一步。
2. **确定状态转移公式（递推公式）**  
   但页面强调：**递推公式只是 DP 的一部分，不是全部**。
3. **初始化 dp 数组**  
   初始化往往由递推公式决定，因此必须先确定递推公式再初始化。
4. **确定遍历顺序**  
   遍历顺序错误会导致 dp 推导错误，是 DP 常见 bug 来源之一。
5. **举例推导 dp 数组**  
   页面极度强调：**写代码前必须手动推一遍 dp 表**，否则容易陷入"黑盒 DP"。


## 3. 动态规划常见误区
- **只背递推公式，不理解 dp 数组含义** → 容易 AC 但不理解本质。
- **照葫芦画瓢**：看题解 → 改代码 → 过不了就乱改 → 恶性循环。
- **黑盒式 DP**：不知道初始化为何这样、遍历顺序为何如此。

## 4. 如何 Debug 动态规划

### Debug 三连问
1. **我是否手动推导过 dp 表？**  
2. **我是否打印过 dp 数组？**（最有效的 debug 方法）  
3. **打印结果是否与我推导一致？**  

如果一致 → 递推公式/初始化/遍历顺序有问题  
如果不一致 → 代码实现细节有问题
